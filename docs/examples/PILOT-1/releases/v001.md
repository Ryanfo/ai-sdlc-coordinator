# Release proposal

> Provenance (ticket, revision, accepted candidate SHA) is added by the coordinator.

## Release notes
The task list now has a title search box next to the existing status filter. Type any text
to narrow the list to tasks whose title contains it (not case-sensitive); clear the box to
see the full list again. If nothing matches, the list area shows an explicit "No tasks match
the current filter." message instead of going blank. The search box has a visible "Search"
label and can be reached and used with the keyboard alone. Search matches the task title
only, not the description; this only affects the checked-in sample task data, with no
external API, authentication, or deployment changes.

## Smoke checks
1. Check out the candidate commit (`be65a480e2015f78a93eef191ba0c88aafaff177`) and run
   `npm ci`.
2. Run `npm run dev` and open the app in a browser.
3. Confirm the task list renders with its existing status filter and a new, visibly labelled
   "Search" text box next to it.
4. Type a substring of an existing task's title (e.g. part of "Onboard new starter", such as
   "onboard") in a different case than it appears (e.g. "ONBOARD") and confirm the list
   narrows to only the matching task(s) (AC1).
5. Clear the search box and confirm the full list reappears (respecting any active status
   filter) (AC2).
6. Type text that matches no task title (e.g. "zzzzz") and confirm the list area shows the
   visible "No tasks match the current filter." message instead of an empty list (AC3).
7. Using only the keyboard (Tab to reach the field, or click once then use only the keyboard
   afterward), type and then clear search text, confirming the control can be operated and
   its label is visibly associated (AC4).
8. Confirm the pre-existing status filter and starred-task behaviour are unaffected.
9. Optionally rerun the full configured checks locally: `npm run lint`, `npm run typecheck`,
   `npm run test:unit`, `npm run build`, `npm run test:e2e`.

## Rollback
1. This is a pure UI/domain change with no persisted state, storage format, or schema
   touched — the search text lives only in transient component state and is never written to
   `KeyValueStore`.
2. To roll back, revert the release commit (or the five changed files: `src/domain/filter.ts`,
   `src/domain/filter.test.ts`, `src/App.tsx`, `src/App.test.tsx`, `e2e/app.spec.ts`) on
   `main` and redeploy/release the prior commit.
3. No data migration, backfill, or cleanup is required after rollback.
